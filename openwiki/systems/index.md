# Files

- [Dashboard REST API surface](dashboard-api.md) - Map of the FastAPI routers Mail2Firefly exposes under /api/v1 — status, sync, logs, transactions, rules, mailboxes with sample fetching, regex preview, AI regex suggestion, Firefly settings, generic settings and Firefly autocomplete — plus the legacy /api aliases and the response shapes the Vue app depends on.
- [Email body extraction contract](email-body-extraction.md) - How Mail2Firefly turns an email into the text a rule regex matches against — the plain part and the HTML part concatenated, why the plain part alone breaks bank alerts, and the invariant that the rule wizard's sample text is produced by the same helper as the sync pipeline.
- [IMAP ingestion and query building](email-ingestion.md) - How Mail2Firefly connects to mailboxes, translates rule conditions into IMAP search strings (including NOT and AND/OR connectors), de-duplicates fetched UIDs, and uses a keyword tag to avoid re-importing processed messages.
- [Firefly III transaction building and posting](firefly-posting.md) - How parsed transaction details plus rule mappings become a Firefly III payload — mapping resolvers (regex group, IMAP field, fixed, Firefly value), placeholder substitution, the Firefly field whitelist loaded from the built frontend bundle, transaction type selection and HTTP error handling.
- [Persistence: MySQL schema and data access](persistence.md)
- [Rule authoring wizard](rule-authoring-workflow.md) - The four-step Vue wizard that creates a parsing rule — basic info, trigger conditions, pattern matching against a live email sample with regex preview and AI suggestion, and destination mapping to Firefly fields — plus how the rule is validated and persisted.
- [Regex transaction parsing and field mapping](transaction-parsing.md) - How Mail2Firefly compiles configured regex patterns into matchable objects, maps named capture groups onto transaction fields with per-pattern overrides, normalises amounts and dates, and converts timestamps to the configured timezone.
